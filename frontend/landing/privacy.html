Privacy and data handling

SALUS is a hackathon prototype. Everything on this page describes the demo build, not a commercial service.

What the demo stores

  • Cell level fingerprints, sensitivity labels, column names, counts, and file hashes.
  • Synthetic event records for downloads, copies, external shares, and investigation intake.
  • Match results, risk assessments, reports, and an audit trail of demo actions.

What the demo does not store

  • Raw file contents after parsing. Uploads are parsed in memory and are not kept as files.
  • Real personal data. The public demo is synthetic and must not receive production data.
  • Screenshots, USB activity, or activity outside connected or simulated sources.

Simulated events

Downloads, copies, and external shares in the demo are generated by a simulator. The interface labels them as simulated. A similarity match never creates a download or share event.

Canaries and watermarks

Canary rows are synthetic decoy records issued to a named recipient. The export watermark is a weak signal stored in XLSX document properties. Both can be removed from a copy, and neither is used as the only evidence.

No covert surveillance

Everything the demo monitors is visible and authorized. There is no endpoint agent and no hidden collection. The demo cannot see USB copies, screenshots, retyped data, or sources that are not connected.

A match is a lead, not proof

Similarity evidence shows that records overlap. It does not prove who copied a file or why. Every incident states this limit.
