The problem

A leaked spreadsheet does not keep its original name.

By the time a small business hears about a leak, the file has a new name, fewer columns, and no history. The customer list is already outside, and the owner has no way to answer three simple questions.

  • What left?
  • Who moved it?
  • What do I do now?

Enterprise data tools assume a security team. A team of 10 to 100 people rarely has one.

What SALUS does

Investigation first, not another blocklist.

When a sensitive file is already outside, blocking the next download does not answer the question. SALUS starts from the copy and works back to the source.

  1. 01

    Find partial copies, not just identical files.

    Cell level Data DNA survives a rename, an XLSX to CSV conversion, deleted columns, and dropped rows.

  2. 02

    Check Indian IDs properly.

    Aadhaar with the Verhoeff checksum, PAN, GSTIN with its own check digit, UPI IDs, phone numbers, and financial fields.

  3. 03

    Follow a trail that points to real events.

    Every lineage edge references a stored event or a stored match. Similarity never invents a download.

  4. 04

    Get a risk score you can defend.

    Four visible factors, a deterministic formula, and a behaviour model that names its top contributors.

  5. 05

    Leave with next steps.

    A grounded report that says what left, who moved it, and what to do now. The fallback report always works.

Evidence, not guesses

The ghost copy is built to be hard.

The demo copy is renamed, converted to CSV, stripped of its watermark, reduced to 300 rows, and missing three columns. SALUS still recovers 30 percent of the source records and finds the canary.

  • Cell hashes ignore column names, so deleted columns do not break the match.
  • Rare values carry more weight than common values.
  • The canary shows which issuance the copy came from.
  • A match is a lead, not proof of intent.

What SALUS cannot see

  • USB copies, screenshots, and retyped data.
  • Activity outside connected or simulated sources.
  • A canary or watermark that was removed.
  • Intent. A match is a lead, not proof.

Questions

What owners ask before they try it.

The demo is open. No signup, no card, and no production data.

Is SALUS a DLP product?

No. DLP blocks known patterns at a gateway or endpoint. SALUS investigates a file that is already outside and links it to the source, the actor, and the stored events.

What does SALUS store?

Fingerprints, labels, counts, and metadata. Raw uploads are parsed in memory and are not kept as file contents.

Can it see USB copies, screenshots, or retyped data?

No. It can only see events from connected or simulated sources. Those limits are shown in every incident.

How do you avoid false positives?

Rare value weighting, a minimum of one rare matched cell, coverage checks, and an explicit rule that a match is a lead, not proof. The report shows the evidence.

Does it work with Google Workspace?

Not in this build. The event schema and lineage are ready for a Drive Activity and Admin Reports connector in the next phase.

What happens if Gemini is unavailable?

The deterministic composer produces the same report structure from the evidence. The UI shows which provider wrote the report.

Is the demo using real data?

No. Every record is synthetic, including the canary rows. Simulated events are labelled.

What does it cost?

The demo is free. Pilot pricing is not set. The goal is a tool small businesses can afford without a security team.
